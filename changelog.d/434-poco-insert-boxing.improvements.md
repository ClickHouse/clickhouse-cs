* Mostly eliminated allocations in POCO binary inserts: value-type properties are now written through box-free delegate instead of boxing each value into `object` and unboxing it inside the type's `Write`. This removes one heap allocation per matched value per row on the `RowBinary` POCO insert path (`client.InsertBinaryAsync(table, pocos)`). In a 500k-row insert of a 3-column POCO (`Int64`, `String`, `Float64`), managed allocations dropped ~37% (62.4 MB → 39.5 MB), Gen2 collections were eliminated, and performance improved by over 10%. Note that if you use `RowBinaryWithDefaults`, the path is unchanged and still incurs the boxing cost. The change only applies to `RowBinary` (the default).
