* **Query responses are now compressed with zstd instead of gzip by default.** The driver advertises `zstd, lz4, gzip, deflate`, and ClickHouse's fixed preference order resolves that to zstd. Bodies are decoded transparently as before, so no code change is needed — but the codec on the wire changes, and with it the CPU/bandwidth trade. Measured against `lz4`, the other cheap codec: at the shipped `http_zlib_compression_level` (3) zstd sends 22-26% fewer bytes for 40-51% less server CPU, but at level 1 it costs 10-18% *more* server CPU, and it is slower to decode client-side (~0.7-1.4 GB/s against lz4's ~1.1-2.3), which the driver does on the calling thread. Set `AcceptEncoding = "lz4"` (or `"gzip"`, the previous default) on the settings, the connection string, or a single query to choose the codec yourself.
