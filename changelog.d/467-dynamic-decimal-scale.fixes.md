* Fixed scalar `decimal` and `ClickHouseDecimal` values written to a `Dynamic` column (or an unhinted `JSON` path) being truncated to 9 fractional digits. Such a value is now stored as the narrowest `Decimal32`/`Decimal64`/`Decimal128`/`Decimal256` that holds it, with the largest scale that width allows. Reading a `Decimal128`/`Decimal256` value as `decimal` (with `UseCustomDecimals=false` or through `GetDecimal`) no longer overflows when the value fits `decimal` but is stored with a scale above 28 or more than 29 digits (issue #466).
