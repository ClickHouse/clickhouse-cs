* **Dynamic credential rotation** (issue #395): new `ClickHouseClientSettings.CredentialsProvider` callback (`Func<ClickHouseCredentials>`), evaluated once per HTTP request, allowing rotation of basic credentials or bearer tokens without recreating the client or connection. Construct results via `ClickHouseCredentials.CreateBasic(username, password)` or `ClickHouseCredentials.CreateBearer(token)`. Precedence for the Authorization header: per-query `BearerToken` override > provider result > static `BearerToken` > static `Username`/`Password`; a `null` provider result falls back to the static settings. The callback is synchronous and must be thread-safe; providers that acquire tokens asynchronously should refresh in the background and return the cached value. Programmatic only (no connection-string key), like `BearerToken`. Minor edge-case change: setting a per-query/command `BearerToken` override to an empty string is now equivalent to not setting it (`null`) — the connection-level `BearerToken` (or credentials provider) applies as normal. Previously an empty-string override suppressed the connection-level bearer token and forced Basic auth with `Username`/`Password`.
