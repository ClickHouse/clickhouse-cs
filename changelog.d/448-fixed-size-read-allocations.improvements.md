* Reduced per-row allocations when reading fixed-size binary columns. `Int128`/`Int256`/`UInt128`/`UInt256`, `Decimal128`/`Decimal256`, `IPv4`, and `IPv6` no longer allocate a temporary `byte[]` per value during deserialization — the raw bytes are read into a stack-allocated buffer before being handed to `BigInteger`/`IPAddress` (which copy). `FixedString` reads (default string mode) now read into a stack buffer for lengths ≤ 256 bytes and a pooled buffer above that, instead of a fresh `byte[]` per row. In a 200k-row read benchmark (single column, `GetValue`), managed allocations per read dropped e.g. `Int256` −64% (16.8 MB → 6.1 MB), `UInt256` −67% (18.3 MB → 6.1 MB), `Decimal256` −58% (18.3 MB → 7.7 MB), `IPv4` −44% (13.8 MB → 7.7 MB), `FixedString(512)` −34% (302 MB → 200 MB), with a corresponding drop in Gen0 collection frequency. Behavior is unchanged (including two's-complement decoding of signed integers/decimals and IPv4 byte-order reversal); the residual per-row allocation is the boxed result object itself. The `ReadStringsAsByteArrays`/`ReadAsByteArray` mode is unchanged, since that buffer is returned to the caller as the column value.
