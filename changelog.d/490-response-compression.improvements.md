* **Query responses are now compressed with `lz4` instead of `gzip`.** It is cheaper for the server to compress and for the client to decompress, and it is applied transparently, so most applications need no change. Compression was already on by default; only the codec changed. Set `AcceptEncoding` to pick a different one, or `identity` to turn it off.
* **A custom `HttpClient` no longer needs `AutomaticDecompression`.** The driver decompresses responses itself, so supplying your own `HttpClient` (or `IHttpClientFactory`) no longer risks unreadable data. If you do set `AutomaticDecompression`, prefer leaving it at its default of `None`: .NET adds the codecs in its mask to your outgoing `Accept-Encoding` and can therefore override the codec you asked for.
* **Clearer failures around compression.** A response compressed with a codec the driver cannot read (e.g. `zstd`) now raises an error naming that codec and how to fix it, instead of failing as a confusing type-parse error. Server error messages are now readable when the response is compressed, rather than surfacing as binary.
* `deflate` responses are now read correctly. ClickHouse sends `Content-Encoding: deflate` in the zlib format that HTTP specifies, which the driver previously could not parse; both that and the raw form are now handled.
