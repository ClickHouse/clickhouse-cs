* Fixed uncompressed binary inserts (`InsertOptions.Compressor = null`) inflating the HTTP request body (issue #524). The request body is sent chunked, and the row serializer wrote straight to it, so every field write became its own HTTP chunk — a 1000-row one-column `Int64` insert sent 1001 chunks of 8 bytes and 13,569 wire bytes to carry 8,000 bytes of data (+70%; ~+25% on a 15-column schema). The payload now passes through the same 256 KiB write buffer the compressed path already used, so it reaches the transport in a handful of large chunks. Compressed inserts are unaffected.
